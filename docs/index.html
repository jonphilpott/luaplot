luaplot

A Lua-scriptable toolkit for pen plotters running GRBL.

Overview

luaplot lets you write Lua scripts that drive a pen plotter directly over serial, render to SVG for previewing, or save G-code to a file for repeatable playback. Lua 5.4 is bundled — the only dependency is a C compiler.

The API is modelled on Processing: a push/pop transform stack, Y-down coordinates, and simple drawing primitives. luaplot takes care of Y-axis flipping, pen servo control, and GRBL flow control so your scripts stay readable.

Building

First-time setup — downloads Lua 5.4.7 source into lua-src/:

make fetch-lua

Then build the luaplot executable:

make

Run a script:

./luaplot examples/hello.lua

Pass extra arguments after the script name — they are available to the script as arg[1], arg[2], etc.

Output modes

./luaplot --help lists the options, the bundled tools, the environment variables, and where it resolved its module directory from — useful when require 'plotter' is not finding anything.

The mode field in plotter.init() controls where output goes.

ModeDescription
serial Send G-code to the plotter in real time. Each command blocks until GRBL replies ok, preventing buffer overrun.
svg Write an SVG file. No hardware required — good for previewing and iterating on a design.
gcode Write a .nc G-code file. Send it to the plotter later with any G-code sender for repeatable results.
both Send to the serial port and write an SVG simultaneously.
both means serial plus SVG, not plus G-code. gcode_file is only written in gcode mode — in both the G-code goes down the wire rather than into a file. To keep a copy of a live plot, run the script twice.

Coordinate system

luaplot uses a Y-down, origin top-left coordinate system in scripts — the same as Processing and most drawing APIs. Positive X goes right, positive Y goes down.

GRBL homes to the bottom-left of the work area with Y increasing upward. luaplot flips Y automatically when emitting G-code: 

gcode_y = height - lua_y

SVG also uses Y-down, so no conversion is needed there. You never need to think about this unless you are reading the raw G-code output.

Placing the page on the bed

width and height say how big the page is. origin says where it sits — the machine coordinates of the paper's near-left corner, the same corner and the same numbers pen-setup.lua takes as --origin. 

plotter.init {
    mode   = "serial",
    port   = port,
    width  = 180,
    height = 240,
    origin = vec2(43, 127),   -- where the paper actually is
}

Supplying it changes which coordinate frame the plot is emitted in, and that is the part worth understanding:

Behaviour
origin omitted The preamble sends G92 X0 Y0, making wherever the head is parked the corner of the page. Nothing needs homing — park the head and plot. This is the original behaviour and remains the default.
origin given Every move is emitted with G53 — absolute machine coordinates — so the plot lands in the same physical place every run. Needs the machine homed.
Why G53 rather than clearing offsets. G92.1 cancels a G92 offset but not a G54 one, which lives in EEPROM and survives everything — so a machine carrying, say, a −199 mm G54 offset would silently place the whole plot 199 mm from where it was asked to go. Stating the frame on every block removes the assumption: no offset of any kind can displace the output, and nothing has to be cleared first.
The plot is checked against the machine's travel before anything moves. luaplot reads $130/$131 (maximum travel) and $23 (homing direction) and refuses to start if the page will not fit: 
luaplot error: this plot does not fit the machine and would drive into its limits.
    X: the plot needs 4.0 to 283.0 mm, the machine reaches -300.0 to 0.0 mm ($130 = 300.0)
    Y: the plot needs 4.0 to 360.0 mm, the machine reaches -380.0 to 0.0 mm ($131 = 380.0)
That $23 matters more than it looks. A set bit means the axis homes toward its maximum, which puts machine zero at that end and makes the entire working area negative on that axis. On such a machine a small positive origin like (4, 4) is not slightly wrong — it is unreachable, and the head drives into the frame trying to get there. Read the real numbers with jog.lua.

This check needs to interrogate the machine, so it only runs in serial mode. It is worth enabling GRBL's own soft limits ($20=1) as well — that is the backstop that protects everything, including G-code sent by other software.
If your machine boots into an alarm, use an explicit origin. A machine with homing enabled refuses G-code until it has homed, so scripts need home = true — and homing can move, or on some builds reset, the work offset. A stored origin then cannot survive the very homing cycle that has to happen first.

origin = vec2(x, y) is immune: every move carries G53, so no offset of any kind can displace it. Pair it with home = true and the plot lands in the same place every run regardless of what homing does.

luaplot compares the offset before and after homing and warns if it moved, rather than letting a plot come out quietly a few millimetres out.

Finding the numbers

jog.lua is built for this: jog to the near-left corner of the paper, press 0, and the machine column reads your origin. Jog to the far corner and the work column reads your width and height.

The origin is a machine-space offset, so it does not disturb anything in drawing space: plotter.paths(), bounds() and the clip window are all still relative to the page. Clipping means on the paper, wherever the paper happens to be. It has no effect on SVG output at all.

Transform stack

luaplot maintains a stack of 2D affine matrices. Every drawing call transforms its coordinates through the matrix at the top of the stack before output.

push() saves the current transform; pop() restores it. Calls to translate(), rotate(), and scale() modify the current matrix in place. Transforms compose in the order you write them — the same as Processing. 

-- draw a rectangle rotated 30° around the point (100, 100)
plotter.push()
  plotter.translate(100, 100)   -- move origin to pivot point
  plotter.rotate(30)            -- rotate 30° clockwise
  plotter.translate(-25, -25)  -- shift so rect is centred on origin
  plotter.rect(0, 0, 50, 50)
plotter.pop()
-- back to whatever transform was active before push()

The matrix is a standard 2D affine transform stored as six values {a, b, c, d, tx, ty}: 

x' = a·x + b·y + tx
y' = c·x + d·y + ty

API reference

All functions are on the table returned by require 'plotter'.

Points and vec2

Anywhere luaplot expects a point you may pass either two numbers or a single vec2. Plain {x, y} tables work too, so older scripts keep running unchanged. 

plotter.line(10, 10, 90, 90)
plotter.line(vec2(10, 10), vec2(90, 90))

-- point lists can mix the two freely
plotter.polyline({ vec2(0,0), {10,10}, vec2(20,0) })

This works because a vec2 answers v[1] and v[2] as well as v.x and v.y — it is a C userdata with a metatable, not a table, but it indexes like one.

Angles disagree between the two APIs, deliberately. plotter.rotate() takes degrees, matching Processing's sketch-level API. vec2:rotate() takes radians, matching PVector and math.sin/math.cos. Every angular vec2 method has a _deg twin — rotate_deg, heading_deg, angle_between_deg, vec2.from_angle_deg — so you never have to convert by hand.

Pen values are machine-specific. The pen_up / pen_down defaults of S90 / S30 suit some other plotter's servo, not necessarily yours, and a pen driven to the wrong position lands hard. luaplot warns if you use serial mode without setting both. tools/calibrate.lua and plotter.servo() are how you find the right numbers.

Clipping

Geometry outside the work area is a real hazard: a plotter asked to move past its limits will happily try, and either lose steps or drive into its own frame. clip decides what happens.

ValueBehaviour
"warn"Draw it anyway, but print one warning to stderr naming the offending primitive. The default: noisy enough to notice, never silently alters your drawing.
"clip"Trim geometry to the work area boundary. A path that leaves and re-enters comes back as several separate paths; a clipped closed shape becomes open.
"off"No checking. Fastest, and correct when you are deliberately working outside the nominal area.
 
local plotter = require 'plotter'

plotter.init {
    mode     = "svg",
    width    = 200,
    height   = 200,
    svg_file = "my_drawing.svg",
}

plotter.push()

Save the current transform matrix by pushing a copy onto the stack.

plotter.pop()

Restore the transform saved by the last push().

plotter.translate( dx, dy )

Move the origin by dx, dy.

plotter.rotate( angle )

Rotate the coordinate system by angle degrees clockwise (in Y-down space). The rotation is around the current origin — use translate() first to rotate around an arbitrary point.

plotter.scale( sx [, sy] )

Scale the coordinate system. If sy is omitted, uniform scaling is applied. Passing different values for sx and sy will produce non-uniform scaling — a circle primitive becomes an ellipse, for example.

plotter.line( x1, y1, x2, y2 )

Draw a straight line from (x1, y1) to (x2, y2). The current transform is applied to both endpoints.

plotter.rect( x, y, w, h )

Draw a rectangle. (x, y) is the top-left corner; w and h are width and height. Drawn as four separate lines, so the transform applies naturally — rotating the coordinate system rotates the whole rectangle.

plotter.circle( cx, cy, r [, steps] )

Draw a circle centred at (cx, cy) with radius r, approximated as a polygon with steps sides (default 36). Increase steps for smoother circles at large sizes.

Applying scale() before drawing a circle produces an ellipse.

plotter.text( x, y, str, height )

Draw str using the Hershey Roman Simplex single-stroke font. (x, y) is the left end of the baseline; height is the cap height in drawing units. Returns the total advance width so calls can be chained.

Single-stroke fonts are ideal for plotters — each letter is drawn with the minimum number of pen lifts.

plotter.text_width( str, height )

Returns the advance width of str at the given cap height in drawing units, without drawing anything. Use this to calculate positions before calling text() — for example to centre or right-align a string.

plotter.polyline( points [, close] )

The core primitive. Draw a connected path through a list of {x, y} tables. If close is true, a final segment is drawn back to the first point. The pen goes down once at the start and up once at the end — far more efficient than calling line() repeatedly for connected paths. 

plotter.polyline({ {10,10}, {50,30}, {90,10} }, false)  -- open path
plotter.polyline({ {10,10}, {50,80}, {90,10} }, true)   -- closed triangle

plotter.polygon( points )

Draw a closed shape through an arbitrary list of {x, y} points. Equivalent to polyline(points, true). 

-- equilateral triangle
plotter.polygon({ {100,60}, {135,120}, {65,120} })

plotter.arc( cx, cy, r, start_angle, end_angle [, steps] )

Draw a portion of a circle. Angles are in degrees, measured clockwise from the positive X axis (consistent with Y-down screen space). steps defaults to a value proportional to the angular span. 

-- semicircle opening downward
plotter.arc(100, 100, 40, 0, 180)

-- three-quarter arc
plotter.arc(100, 100, 40, 0, 270)

plotter.ellipse( cx, cy, rx, ry [, steps] )

Draw an ellipse centred at (cx, cy) with horizontal radius rx and vertical radius ry. Unlike scale() + circle(), this does not affect the current transform. 

plotter.ellipse(100, 100, 60, 30)  -- wide flat ellipse

plotter.bezier( x1, y1, cx1, cy1, cx2, cy2, x2, y2 [, steps] )

Draw a cubic Bézier curve from (x1, y1) to (x2, y2). (cx1, cy1) and (cx2, cy2) are the control points that pull the curve. steps defaults to 20.

The cubic Bézier formula: P(t) = (1-t)³P₀ + 3(1-t)²t·P₁ + 3(1-t)t²·P₂ + t³P₃ where t runs from 0 to 1. 

-- gentle S-curve
plotter.bezier(40, 150,   40, 60,   160, 140,   160, 50)
local advance = plotter.text(10, 50, "Hello", 20)
plotter.text(10 + advance, 50, " world", 20)

plotter.penup()

Lift the pen. Sends M3 S<pen_up> followed by a short dwell so the servo reaches position before the next move. Has no effect if the pen is already up.

The dwell after a pen move is not decoration. M3 tells the servo where to go; it says nothing about when it arrives, and GRBL starts the next move immediately. If the pen is still on its way up when a rapid begins, it draws the rapid — a line straight across the finished work, usually the long diagonal to the parking position.

pen_delay has to cover your servo's actual travel time. The 0.1 s default is brisk; a servo needing 0.3 s will smear every lift in the plot, and the parking traverse is just where it shows up worst. It is paid twice per path, though, so a thousand-path plot notices a generous value — time it rather than guessing high.

plotter.penup(true) forces the lift even when the pen is already believed to be up. done() uses this before parking, because servo() and dip() move the pen without updating the tracked state, so "already up" is not always true.

plotter.pendown()

Lower the pen onto the paper. Sends M3 S<pen_down> and a dwell. Has no effect if the pen is already down.

Note: The drawing primitives (line, rect, etc.) manage the pen automatically — you only need penup() and pendown() if you are building custom motion sequences directly.

Shape building

plotter.point( x, y )

Mark a single position. A plotter cannot draw a zero-length line — the pen would go down and straight back up, leaving at best a faint dot — so this draws a very short stroke instead, dot_size mm long.

plotter.rounded_rect( x, y, w, h, r [, steps] )

A rectangle with quarter-circle corners of radius r. steps is segments per corner (default 6). r is clamped to half the shorter side, so an over-large radius gives a stadium shape rather than a self-crossing mess.

plotter.regular_polygon( cx, cy, r, n [, rotation] )

An n-sided regular polygon inscribed in a circle of radius r. rotation is in degrees; the default puts a vertex straight up, which is how a triangle or pentagon is normally drawn.

plotter.grid( x, y, w, h, cols, rows )

A grid of cols × rows cells filling the rectangle, border included. Emitted as full-length lines rather than per-cell rectangles: for a 20×20 grid that is 42 pen lifts instead of 400.

plotter.begin_shape() / vertex( x, y ) / end_shape( close )

Accumulate points one at a time and draw them as a single path — for when the vertices come out of a loop and collecting them into a table first would just be noise. 

plotter.begin_shape()
for a = 0, 350, 10 do
    plotter.vertex(vec2.from_angle_deg(a) * 40 + vec2(100, 100))
end
plotter.end_shape(true)

plotter.curve( points [, close [, steps [, tension]]] )

A smooth curve that passes through every given point — Processing's curveVertex(), a Catmull-Rom spline. Unlike bezier(), whose control points only pull the curve toward them. tension (default 0.5) scales the tangents: 0 gives straight lines, higher values bulge more.

plotter.curve_points( points [, close [, steps [, tension]]] )

The smoothed point list curve() would draw, returned rather than drawn — the same split as streamline().

This is what makes a smooth shape hatchable: hatch() wants a polygon, and a handful of control points is not one. Sketch the outline with a few points, run it through here, and fill the result. 

local outline = plotter.curve_points(control_pts, true)
plotter.hatch(outline, 45, 2)
plotter.polyline(outline, true)

tension is worth knowing about when the shape carries detail: the default 0.5 is a soft flowing curve, and around 0.25 keeps corners crisp enough to survive. At the default, a 5 mm scallop smooths straight back into an oval.

plotter.quad_bezier( x1, y1, cx, cy, x2, y2 [, steps] )

Quadratic Bézier — one control point instead of two.

Hatching and fills

plotter.hatch( shape, angle, spacing [, opts] )

Fill a closed shape with parallel lines. A plotter cannot fill a region — it only draws strokes — so hatching is how tone and solidity get made.

ArgumentMeaning
shapeA list of points, or a list of such lists. When several are given the first is the outline and the rest are holes.
angleHatch direction in degrees.
spacingDistance between adjacent lines, mm.
opts.insetPull the fill in from the outline by this much (default 0).
opts.outlineAlso stroke the shape's boundary (default false).
opts.zigzagJoin alternate line ends into one continuous path (default false).
 
local shape = {{20,20}, {180,20}, {180,180}, {20,180}}
local hole  = {{80,80}, {120,80}, {120,120}, {80,120}}

plotter.hatch({shape, hole}, 45, 2, { outline = true })

Concave shapes and holes come out right because crossings are paired by the even-odd rule — a point is inside when a ray to it has crossed an odd number of edges.

Holes must lie inside the outline. The even-odd rule cannot tell a hole from an outline, so a hole poking outside the shape it is cut from gets filled rather than cleared — which looks like the fill has leaked. If two regions need to punch each other out of a third, make them adjoin rather than overlap: two overlapping holes fill their intersection back in for the same reason.
Use zigzag on dense fills. Without it every scanline is a separate path costing its own pen lift, and a tightly hatched shape can spend most of its time lifting rather than drawing. With it, alternate lines are joined end to end into a single continuous path — one lift for the whole fill. It only applies where a scanline has exactly one span, so a shape that splits around a hole still breaks the path there rather than drawing across the gap.

Streamlines

plotter.streamline( start, field_fn, steps, step_len [, opts] ) → points

Trace a path through a vector field and return the points. It does not draw anything, so you can trim, filter or thin the result before handing it to polyline().

field_fn(p) is called with a vec2 and must return a direction: a vec2, an {x, y} table, or two numbers. Magnitude is ignored — only direction — so a field of wildly varying strength still advances at a steady step_len.

OptionMeaning
opts.stopPredicate called with the current point; return true to end the trace early.
opts.min_magGive up where the field goes slack (default 1e-9).
 
local function field(p)
    local a = noise.fbm(p.x * 0.01, p.y * 0.01) * math.pi * 2
    return vec2.from_angle(a)
end

plotter.polyline(plotter.streamline(vec2(10, 10), field, 200, 1.5))

Integration is midpoint (RK2), not Euler: the field is sampled, a half step taken, and the field sampled again before committing. Euler visibly spirals outward on curved fields, which on paper reads as drift rather than flow.

See the flow field example for the full technique, including keeping neighbouring lines from converging into a blot.

Painting with a brush

A brush holds a finite amount of paint, so a painting is a sequence of strokes punctuated by trips back to a pot on the bed. luaplot models the pot as a fixed position and the reload as a queued action.

plotter.pot( name, x, y )

Register a paint pot. The two-argument forms — plotter.pot(x, y) or plotter.pot(vec2) — register the default pot, used when dip() is called with no name. Pots can also be declared up front as paint_pot / paint_pots in init(). 

plotter.init {
    mode      = "serial",
    port      = port,
    pen_up    = 0,
    pen_down  = 150,

    paint_pot = vec2(15, 15),
    pen_dip   = 175,      -- the paint is deeper than the paper
    dip_time  = 1.5,      -- seconds in the paint
    drip_time = 2.0,      -- seconds above the pot, letting excess fall back
}

-- or several, named
plotter.pot("red",   vec2(15, 15))
plotter.pot("black", vec2(15, 45))
Pot positions are absolute and the transform stack never touches them. The pot is a physical object bolted to the bed: it does not move because your drawing is translated, rotated or scaled. Both pot() and dip() bypass the stack entirely, so a dip inside a push()/pop() block still goes to the same place. A dip that went through the transform would end up somewhere else on the bed, at rapid speed.

plotter.dip( name, opts )

Reload the brush. Both arguments are optional. The sequence is:

  1. pen up
  2. rapid to the pot
  3. pen down into the paint (pen_dip)
  4. wait dip_time
  5. pen up
  6. wait drip_time, so excess paint drips back into the pot
plotter.dip()
plotter.dip("red")
plotter.dip("red", { dip_time = 3, drip_time = 2 })
plotter.dip({ pen_dip = 180 })      -- deeper, default pot

opts overrides dip_time, drip_time or pen_dip for one dip — a thin wash wants a shorter soak than thick acrylic, and the first dip of a session often wants a longer one to prime dry bristles.

Which produces:

G0 X15.000 Y185.000     ; travel to the pot, brush clear
M3 S175                 ; down into the paint
G4 P1.500               ; dip_time
M3 S0                   ; lift out
G4 P2.000               ; drip_time, over the pot
The second wait is the one people leave out. A brush comes out of the pot loaded and dripping. Lifting and immediately traversing to the drawing flings paint across the page; waiting over the pot lets the excess fall back where it belongs.

Dips keep their place in the sequence

dip() does not fire immediately. Like a stroke, it is queued in the path buffer, because a dip is an ordered event — "these strokes get this load of paint" only means anything if the dip stays put relative to the strokes around it.

It follows that a dip is a hard barrier for the travel optimiser. Paths are freely reordered between two dips, never across one. After a dip the pen is at the pot, and the optimiser picks up from there.

Automatic reloading

Set dip_every to a distance in mm and luaplot tops the brush up before any stroke that would run past that budget. A manual dip() resets the budget. 

plotter.init { ... paint_pot = vec2(15, 15), dip_every = 120 }

-- reloads happen on their own, between strokes, never mid-stroke
plotter.hatch(shape, 45, 3)

The decision is made when the stroke is recorded, not when it is emitted, so it does not shift when paths are reordered — drawn length is the same either way, travel is not.

An automatic reload goes back to the pot you last dipped, so a top-up is the same colour as the paint already on the brush. Failing that the default pot, and failing that the only pot there is. A bare dip() follows the same rule, so it will not silently jump back to the default half way through a two-colour painting.

A stroke longer than the whole budget cannot be helped by reloading — the path would have to be split, which would change the drawing — so it is drawn as-is and luaplot warns once that it may run dry. It will not dip twice in a row on a brush that was only just loaded.

Reloads in the plot summary

plotter.stats() gains dips and dwell_min, and minutes includes the waiting. That matters: at a second in the pot and a second dripping, a painting reloading every 50 mm can spend longer waiting than drawing. 

318 paths  |  4210 mm drawn  |  1870 mm travel  |  36 dips (1.2 min)  |  ~7.3 min

Dips are excluded from plotter.paths() and from plotter.bounds() — a pot is hardware, not artwork, and should not stretch the bounding box. plotter.queue() returns strokes and dips together in emission order, each tagged with a kind of "path" or "dip".

Layers

plotter.layer( name )

Tag everything drawn from here on as belonging to a named layer. plotter.layer(nil) returns to the unnamed default.

  • SVG — each layer becomes a <g> with its own stroke colour, so you can see the separation on screen.
  • Serial / G-code — the pen is parked and you are prompted on stdin to swap pens when the plot crosses a layer boundary. This is how a single-pen plotter draws in more than one colour.
  • Optimisation — paths are never reordered across a layer boundary, so layers double as barriers for the travel optimiser.
plotter.layer("outline")
plotter.rect(10, 10, 180, 180)

plotter.layer("shading")   -- prompts for a pen change on hardware
plotter.hatch(shape, 45, 2)

flush() and real-time plotting

plotter.flush()

Emit every path buffered since the last flush and clear the pending set. The session stays open — the serial port is not closed and you can keep drawing. Safe to call any number of times, including when nothing is pending.

Primitives do not write G-code directly. They transform their points into world space and append to a path buffer; flush() is what turns buffered paths into output. By default auto_flush is on and every primitive flushes immediately, so scripts behave exactly as they always did.

Turning it off is what makes a plot that builds up over time possible — reacting to a sensor, a network feed, or anything else that arrives while the pen is still on the paper: 

plotter.init {
    mode       = "serial",
    port       = port,
    auto_flush = false,
}

while running do
    plotter.polyline(read_sensor())
    plotter.flush()      -- this batch goes to the pen; session stays live
end

plotter.done()

In svg/both mode each flush rewrites the SVG with everything accumulated so far, so you can watch the file grow in a browser that reloads.

flush() versus done(). flush() emits and keeps going. done() emits, parks the pen, writes the output files and closes the port. Use flush() in a loop. done() is idempotent, so calling it more than once is harmless, and plotter.done { keep_open = true } gives you the park and the file write without closing the port.

Travel optimisation

Set optimize = true in init() and luaplot reorders buffered paths before emitting them, so the pen spends less time moving between strokes with nothing to draw.

Pen-up travel is pure overhead, and it dominates far more often than people expect: a stipple or contour plot generated in scan order can easily spend more time in the air than on the paper. On a scattered test of 200 short strokes, reordering cut travel by around 90%.

The algorithm is greedy nearest-neighbour from the pen's current position, reversing a path when its far end is the closer entry point. Not optimal, but O(n²) with a tiny constant and it removes most of the waste.

  • Reordering never crosses a layer boundary.
  • Closed paths are reversed but never rotated to a different start vertex — that would move the seam where the pen sets down and lifts, which is visible on paper.
  • optimize forces auto_flush off: paths have to be held back before they can be reordered. Each flush() optimises one batch, picking up from where the pen actually is.

Bounds and statistics

plotter.bounds() → min, max

Alarms and homing

GRBL boots into an alarm state whenever homing is enabled ($22=1) and refuses every G-code word until it is told where the machine is. This is not an edge case — it is what happens on the first run after the controller powers up, and the failure looks like error:9 on an innocent command.

So a serial script has to say which it wants: 

plotter.init {
    mode = "serial",
    port = port,
    home = true,      -- $H: drive into the limit switches, known position
}

plotter.init {
    mode   = "serial",
    port   = port,
    unlock = true,    -- $X: clear the alarm, move nothing
}

Without either, init() checks and fails with a message naming both options rather than letting the preamble hit a bare error code.

plotter.home()

Run a homing cycle. Blocks until GRBL answers, which it does only once the cycle finishes — routinely 10 to 30 seconds — so the reply timeout is raised for the duration. Needs $22=1; GRBL answers error:5 otherwise.

plotter.unlock()

Clear the alarm without homing. Nothing moves, which makes it safe to call blind, but GRBL is left with no idea where the machine is.

That suits luaplot's coordinate model, which zeroes the work origin wherever the head is sitting (the G92 in the init preamble) — park the head where the drawing should start, unlock, and plot. It does not suit anything relying on machine coordinates or soft limits.

plotter.is_locked()

Whether GRBL is currently refusing G-code. Probed with G4 P0, a zero-length dwell: harmless if accepted, error:9 if not. The obvious probe — the ? status query — is a realtime command that never answers ok, so it would hang until the timeout.

A slow plot is not a hung plot. GRBL acknowledges most commands as soon as they are parsed into its planner buffer, but the synchronising ones — M3/M5 pen moves, G4 dwells, $H — are not answered until every queued move has physically finished. A pen lift after a 200 mm path at 600 mm/min legitimately leaves the port silent for twenty seconds.

So luaplot's reply timeout measures liveness, not speed: when the port goes quiet it sends ?, a realtime status query GRBL answers from an interrupt whatever the planner is doing. An answer resets the clock. Only silence that survives repeated probes is treated as a dead machine. An Alarm appearing in a status report fails immediately, since the ok is never coming; a Hold or Door pause is reported once and then waited out.
Closing the port used to reset the controller. Dropping DTR on close reboots any Arduino-style board, so each run found GRBL freshly booted and alarmed — a homing cycle per plot. luaplot now clears HUPCL, leaving DTR asserted through the close, so the controller keeps running between invocations: home once, then plot as often as you like. The first connection after the board powers up still resets, since DTR has to be asserted from idle at some point.

plotter.moveto( x, y )

Rapid-move (G0) to an absolute position in Lua drawing coordinates (Y-down, origin top-left). Does not move the pen — call penup() or pendown() before or after as needed. The current transform stack is not applied — coordinates are always relative to the work area origin.

Only meaningful in serial or both mode; no-op otherwise. 

-- lift pen, reposition, lower pen
plotter.penup()
plotter.moveto(100, 100)
plotter.pendown()

-- drag (move with pen already down)
plotter.pendown()
plotter.moveto(50, 50)

plotter.servo( s )

Send a raw servo position command M3 Ss with an arbitrary value. Use this during calibration to sweep the servo and find the correct pen-down height before committing the value to pen_down in your init() config. Typical hobby servos wired to GRBL accept values in the range 0–180.

Only meaningful in serial or both mode; no-op otherwise. 

-- sweep the servo to find the right pen-down height
plotter.penup()
plotter.moveto(100, 100)   -- position over paper
plotter.servo(60)           -- try this height
-- pen too high? lower it:
plotter.servo(45)
-- once happy, set pen_down = 45 in plotter.init()
Finding your pen values: set home = true in init(), use moveto() to position the head over your paper, then use servo() to find the right pen-down value. Once you have it, store it as pen_down and remove the calibration calls.
Distances wrong rather than the pen? If a 100 mm line measures 98 mm, that is GRBL's steps-per-mm, not anything in your script. tools/calibrate.lua measures and fixes it, and tools/grbl-config.lua backs the settings up first.

plotter.done()

Finalise output. Always call this at the end of your script.

  • serial / both: lifts the pen, returns to home (G0 X0 Y0), turns off the spindle (M5), closes the serial port.
  • svg / both: writes the SVG file.
  • gcode: writes all accumulated G-code to the output file.

Perlin and Worley noise, in C because noise is usually evaluated across a grid — one call per cell per octave. Available as a global and through require 'noise'.

The fractal variants take octaves (4), lacunarity (2.0) and gain (0.5).

Worley / cellular

Returns the distance to the nearest feature point (f1), the second nearest (f2), and a stable integer id for the winning cell. f2 - f1 is near zero exactly on a cell boundary, which is how you draw the classic cracked-mud web; cell_id lets you make a per-cell decision that stays put as you sample around inside the cell.

opts.jitter (0–1, default 1) is how far feature points stray from their cell centre; opts.metric is "euclidean" (default), "manhattan" or "chebyshev".

Processing compatibility

noise.noise(), noise.noise_detail() and noise.noise_seed() mirror Processing's interface, parameter meanings and 0–1 output range, so sketches port without rescaling. noiseDetail and noiseSeed work too.

Not bit-identical to Processing. Processing's noise() is value noise; this is Perlin. The character of the field is the same, the exact numbers are not.
Noise seeding is separate from math.randomseed. That is deliberate: you usually want to re-roll a sketch's random scatter while holding its noise field still, or the other way round.

Point distributions

util.poisson_disk( w, h, r [, k] )

Blue-noise scatter: points spread randomly over a w × h area but never closer than r to each other. This is the right way to stipple. Uniform random points clump — dense knots and bare patches, which on paper reads as a mistake. Poisson disk has the same irregularity without the clumping.

Bridson's algorithm, linear in the number of points. k is how many placements to try around each point before giving up on it (default 30).

Getting variable density out of it. Generate the scatter at the finest spacing you want anywhere, then keep each point with probability equal to the darkness there. The survivors inherit blue noise's evenness, so a gradient reads as tone rather than texture. See examples/stipple.lua.

util.grid( w, h, cols, rows )

An evenly spaced lattice with points on the edges: the first is (0, 0), the last is (w, h). Row-major, running along x first, so stepping through it in order reads left to right then up. That predictability is the point — tools/pen-setup.lua walks this grid with a person watching each move.

util.halton( i, base ) and util.halton2d( n [, w [, h]] )

A low-discrepancy sequence: even coverage at every prefix length, without being a visible lattice. Unlike poisson_disk you can ask for one more point at any time without recomputing.

camelCase aliases: randomGaussian, randomRange, randomChoice, randomWeighted, smoothStep, poissonDisk.

Finding the servo values

The first thing to run on a new machine. Everything else needs pen_up and pen_down: pen-setup.lua and calibrate.lua both refuse to run without them, and init() warns if you plot in serial mode without setting them, because the built-in defaults suit some other machine's servo. 

$ ./luaplot tools/servo-sweep.lua /dev/cu.usbmodem1101

S> 90
  sent M3 S90
S> 30
  sent M3 S30
Run it with no pen fitted. You are looking for two positions, and a pen in the holder while you sweep is the one thing in reach that can be damaged. Fit the pen afterwards with pen-setup.lua, which lowers the holder first so you can set the height against real paper.

It sends raw serial on purpose — no preamble, no G92, no motion of any kind. The only thing that goes down the wire is M3 S<value>, and nothing is written to EEPROM, so there is nothing to undo.

Measuring your paper

Jog to the near-left corner of the paper and press 0. From then on the work column reads distances from that corner while machine keeps reading from machine zero.

Now jog to the far corner. The work reading there is your paper size; the machine reading back at the near corner is the --origin that pen-setup.lua wants. Both measured rather than guessed, in about a minute.

Home first if your machine has limit switches — machine coordinates only mean anything once GRBL knows where it is. The tool offers to.

Movement uses GRBL's $J= jog commands rather than G0. Jogs leave the modal state alone, so nothing here can change how a later plot is interpreted, and GRBL refuses a jog that would leave the work area when soft limits are on rather than driving into the frame.

Pen setup and bed levelling

Before the first plot of a session: fit the pen at the right height, then check it actually reaches the paper everywhere. A plotter bed is never flat, and a pen set perfectly at the centre can be floating at one corner and gouging at another. 

$ ./luaplot tools/pen-setup.lua /dev/cu.usbmodem1101 \
      --pen-up 0 --pen-down 150 --paper 180,240 --origin 10,15

The tool runs three phases.

1. Attach

The head moves to the middle of the paper and lowers the holder with nothing fitted. You slide the pen in until the nib just touches, and tighten it there. Setting the height with the holder up is guesswork; setting it with the holder down is not.

2. Survey

The head then visits a grid of points across the paper and lowers at each one, pausing so you can look. You are checking that the nib just kisses the paper at every point — not floating, not pressing. 

-- Survey --------------------------------------------------------
Visiting 9 points with the pen down. At each one, check the nib just
touches -- not floating, not pressing.
  Enter  next point      r  lower again here
  q      skip to the dot pass      x  abort
  point 1/9  (row 1, col 1)  X30.0 Y35.0  >
  point 2/9  (row 1, col 2)  X100.0 Y35.0  >

r lifts and lowers again on the spot, so you can watch the nib land after adjusting a shim without losing your place. Points are walked row by row from nearest you, left to right — predictable rather than efficient, since a person is stepping through them.

3. Verify

Finally it revisits every point and puts a dot down without stopping. Nine dots of even weight means you are level. A missing dot is a point the pen never reached; a blot is one where it presses hard. Keep the sheet — it is the record of how your bed sits.

Calibrating steps per mm

If your plotter draws a 100 mm line that measures 98.4 mm, its idea of how many motor steps make a millimetre is wrong. GRBL stores that as $100 for X and $101 for Y, and the correction is a straight ratio: 

new_steps_per_mm = old_steps_per_mm × (commanded / measured)

Draw shorter than asked, and the machine needs more steps per mm. tools/calibrate.lua does the whole loop: 

$ ./luaplot tools/calibrate.lua /dev/cu.usbmodem1101 \
      --pen-up 0 --pen-down 150

  $100 (X steps/mm) = 80.000
  $101 (Y steps/mm) = 80.000

Drawing 100.000 mm X reference line...
Measure the X line tick-to-tick and enter the actual length in mm: 98.4

Drawing 100.000 mm Y reference line...
Measure the Y line tick-to-tick and enter the actual length in mm: 100.7
  Y: 80.000 -> 79.444  (-0.70%)

Measure between the tick marks, not the painted ends. A pen leaves a blob where it sets down and lifts. The perpendicular ticks at each end mark the exact commanded endpoints.

A timestamped backup of every setting is written before anything is changed, so a bad calibration is one grbl-config.lua restore away from being undone. A measurement more than 20% off the commanded length is rejected: at that point something else is wrong — wrong axis, wrong units, a slipped belt — and scaling the setting would only bury the real fault.

GRBL configuration backup

GRBL's settings live in EEPROM. There is no undo, and a wrong value can drive the machine into its own frame. tools/grbl-config.lua exists so that backing up first is easy enough to actually do.

$ ./luaplot tools/grbl-config.lua diff grbl-backup.txt

Placing the page on the bed

width and height say how big the page is. origin says where it sits — the machine coordinates of the paper's near-left corner, the same corner and the same numbers pen-setup.lua takes as --origin. 

plotter.init {
    mode   = "serial",
    port   = port,
    width  = 180,
    height = 240,
    origin = vec2(43, 127),   -- where the paper actually is
}

Supplying it changes which coordinate frame the plot is emitted in, and that is the part worth understanding:

Behaviour
origin omitted The preamble sends G92 X0 Y0, making wherever the head is parked the corner of the page. Nothing needs homing — park the head and plot. This is the original behaviour and remains the default.
origin given Every move is emitted with G53 — absolute machine coordinates — so the plot lands in the same physical place every run. Needs the machine homed.
Why G53 rather than clearing offsets. G92.1 cancels a G92 offset but not a G54 one, which lives in EEPROM and survives everything — so a machine carrying, say, a −199 mm G54 offset would silently place the whole plot 199 mm from where it was asked to go. Stating the frame on every block removes the assumption: no offset of any kind can displace the output, and nothing has to be cleared first.
The plot is checked against the machine's travel before anything moves. luaplot reads $130/$131 (maximum travel) and $23 (homing direction) and refuses to start if the page will not fit: 
luaplot error: this plot does not fit the machine and would drive into its limits.
    X: the plot needs 4.0 to 283.0 mm, the machine reaches -300.0 to 0.0 mm ($130 = 300.0)
    Y: the plot needs 4.0 to 360.0 mm, the machine reaches -380.0 to 0.0 mm ($131 = 380.0)
That $23 matters more than it looks. A set bit means the axis homes toward its maximum, which puts machine zero at that end and makes the entire working area negative on that axis. On such a machine a small positive origin like (4, 4) is not slightly wrong — it is unreachable, and the head drives into the frame trying to get there. Read the real numbers with jog.lua.

This check needs to interrogate the machine, so it only runs in serial mode. It is worth enabling GRBL's own soft limits ($20=1) as well — that is the backstop that protects everything, including G-code sent by other software.
If your machine boots into an alarm, use an explicit origin. A machine with homing enabled refuses G-code until it has homed, so scripts need home = true — and homing can move, or on some builds reset, the work offset. A stored origin then cannot survive the very homing cycle that has to happen first.

origin = vec2(x, y) is immune: every move carries G53, so no offset of any kind can displace it. Pair it with home = true and the plot lands in the same place every run regardless of what homing does.

luaplot compares the offset before and after homing and warns if it moved, rather than letting a plot come out quietly a few millimetres out.

Finding the numbers

jog.lua is built for this: jog to the near-left corner of the paper, press 0, and the machine column reads your origin. Jog to the far corner and the work column reads your width and height.

The origin is a machine-space offset, so it does not disturb anything in drawing space: plotter.paths(), bounds() and the clip window are all still relative to the page. Clipping means on the paper, wherever the paper happens to be. It has no effect on SVG output at all.

Using the transform stack

This example draws a 4×4 grid of squares, the whole grid rotated 15° around its own centre. The key pattern is push / set up transforms / draw / pop. 

local plotter = require 'plotter'

plotter.init { mode = "svg", width = 200, height = 200 }

-- The grid is 4 columns × 4 rows of 11 mm cells (8 mm square + 3 mm gap).
-- Total grid size: 44 mm × 44 mm.  We want it centred at (100, 100).
plotter.push()
    plotter.translate(100, 100)  -- move origin to grid centre
    plotter.rotate(15)            -- rotate 15° clockwise
    plotter.translate(-22, -22)  -- shift so grid is centred on origin

    for row = 0, 3 do
        for col = 0, 3 do
            plotter.rect(col * 11, row * 11, 8, 8)
        end
    end
plotter.pop()

plotter.done()

You can nest push()/pop() pairs to any depth. Each level inherits the parent transform and adds its own on top. 

-- Nested transforms: outer rotation + inner per-cell variation
plotter.push()
    plotter.translate(100, 100)
    plotter.rotate(15)

    for i = 0, 7 do
        plotter.push()                   -- save outer transform
            plotter.translate(i * 10, 0)
            plotter.rotate(i * 5)         -- each cell rotated a bit more
            plotter.rect(-4, -4, 8, 8)
        plotter.pop()                    -- restore outer transform
    end
plotter.pop()

Generative pattern

Concentric rings of circles with increasing angular offset — the kind of thing that takes five minutes to write but looks like it took five hours to plan. 

local plotter = require 'plotter'

plotter.init {
    mode     = "svg",
    width    = 200,
    height   = 200,
    svg_file = "rings.svg",
}

local cx, cy  = 100, 100   -- centre of the composition
local rings   = 6          -- number of concentric rings
local per_ring = 8         -- circles per ring
local r_small = 6          -- radius of each small circle (mm)

for ring = 1, rings do
    local orbit  = ring * 13             -- distance from centre
    local offset = ring * (360 / per_ring / rings)  -- angular stagger

    for i = 0, per_ring - 1 do
        local a  = math.rad(i * (360 / per_ring) + offset)
        local px = cx + orbit * math.cos(a)
        local py = cy + orbit * math.sin(a)
        plotter.circle(px, py, r_small, 24)
    end
end

plotter.done()

To save the G-code for repeatable plotter output, change mode to "gcode": 

plotter.init {
    mode       = "gcode",
    width      = 200,
    height     = 200,
    gcode_file = "rings.nc",
    feed       = 1500,
    pen_up     = 90,
    pen_down   = 35,
}

The resulting rings.nc can be sent to the plotter with any GRBL-compatible G-code sender and will produce identical output every time.

Flow field

The canonical generative plotter piece, and a tour of most of what this page documents: noise for the field, streamline() to trace it, vec2 throughout, and travel optimisation to make the result plottable. The full version is examples/flowfield.lua. 

local plotter = require 'plotter'
local util    = require 'util'

plotter.init {
    mode     = "svg",
    width    = 200,
    height   = 260,
    svg_file = "flowfield.svg",
    optimize = true,
    clip     = "clip",
}

noise.seed(20260820)
math.randomseed(4)

-- A flow field is just a function from position to direction. Mapping fBm's
-- -1..1 onto a full turn makes the field sweep through every direction.
local function field(p)
    local a = noise.fbm(p.x * 0.006, p.y * 0.006, {octaves = 3}) * math.pi * 2
    return vec2.from_angle(a)
end

local function off_page(p)
    return p.x < 8 or p.y < 8 or p.x > 192 or p.y > 252
end

for _, s in ipairs(util.poisson_disk(184, 244, 2.6)) do
    local pts = plotter.streamline(
        vec2(s[1] + 8, s[2] + 8), field, 320, 1.2, { stop = off_page })
    if #pts >= 25 then plotter.polyline(pts) end
end

plotter.done()
The hard part is keeping the lines apart. A flow field attracts. Trace enough lines through one and they converge, pile into the same channels, and the page becomes a solid black blot — an hour of plotting to draw something you cannot see. examples/flowfield.lua adds Jobard and Lefer's evenly-spaced placement on top of the sketch above: as each line is traced, stop it the moment it comes within a set distance of any line already drawn. Occupancy lives in a hash of grid cells so the proximity test looks at nine cells rather than every point so far. In the shipped example that is the difference between 57 minutes of plotting and 9.

A portrait

examples/monalisa.lua — the widest tour of the library here, and a worked answer to a question with no obvious one: luaplot cannot load an image, so how do you draw a picture?

Two things have to be right for a face to read, and they want different tools. Shape is geometry — the oval of the face, the fall of the hair, the slope of the shoulders are curves, so they are drawn as curves, every region a few control points through curve_points(). Tone is light — where a region is dark is a separate question from its outline, so it comes from a separate function: shade(x, y) models one light source and a few soft shadows, returning 0 for paper and 1 for full ink.

Keeping them apart is what stops the picture looking like a colouring book, and lets the tone run across a boundary where the real thing has no edge — which is most of a face.

Every region is then rendered with the mark that suits what it is, the way an engraver would:

RegionMark
backgroundFlat horizontal hatching with the figure as a hole, and curves, an arc and a bezier for the landscape
hairStreamlines combed along its fall, kept apart by a separation test
face, handsPoisson-disk stippling, rejected against shade()
eyes, mouthExplicit circles and curves — the only genuine edges in the picture
dressCross-hatching in passes, the only way a pen reaches near-black
framerect(), plus text() centred with text_width() and a signature rotated through the transform stack

They hold together because every one of them takes its density from the same shade(). Same light, different marks.

Brush painting

examples/brush.lua — a two-colour composition of sweeping strokes, showing what changes when the pen is a brush. See Painting with a brush for the API. 

plotter.init {
    mode      = "serial",
    port      = port,
    feed      = 1200,          -- slower: paint needs time to lay down
    pen_up    = pen_up,
    pen_down  = pen_down,

    paint_pots = {
        ink   = vec2(8, 20),
        ochre = vec2(8, 55),
    },
    pen_dip   = pen_down + 25,   -- the paint sits below the paper
    dip_time  = 1.5,
    drip_time = 2.0,
    dip_every = 180,         -- about one sweep per brush load

    optimize  = true,
}

plotter.layer("ink")      -- one brush per colour, so one layer per colour
plotter.dip("ink")
-- ... long horizontal sweeps ...

plotter.layer("ochre")    -- pauses on hardware so you can swap brushes
plotter.dip("ochre")
-- ... a cluster of vertical marks ...

What actually differs from a pen plot:

  • Fewer, longer strokes. A pen plot can afford ten thousand hairline segments; a brush cannot. The example is around sixty strokes.
  • Strokes sized to a brush load. Each sweep is kept just under dip_every, so it starts fully loaded rather than reloading part-way and fading out.
  • Two colours means two brushes, not two pots. You cannot clean a brush mid-plot, so each colour is a layer — which is exactly what makes the plot pause and ask you to swap.
  • Travel dominates. All those trips to the pot mean the run spends more distance travelling than drawing, and a meaningful slice of its time simply waiting for paint to drip.

Text layout

plotter.text() returns the advance width of the string, which makes it straightforward to chain calls or compute a centred position. 

local plotter = require 'plotter'

plotter.init { mode = "svg", width = 200, height = 150 }

-- Chained text — second word starts where the first ends
local x = 10
x = x + plotter.text(x, 40, "Hello", 18)
x = x + plotter.text(x, 40, ", ", 18)
x = x + plotter.text(x, 40, "world.", 18)

-- Rotated text using the transform stack
plotter.push()
    plotter.translate(20, 130)
    plotter.rotate(-10)
    plotter.text(0, 0, "Tilted label", 12)
plotter.pop()

plotter.done()

To centre a string horizontally, measure it first with plotter.text_width() then draw at the calculated position: 

local label   = "CENTRED"
local cap_h   = 20
local start_x = 100 - plotter.text_width(label, cap_h) / 2
plotter.text(start_x, 80, label, cap_h)
plotter.done()
